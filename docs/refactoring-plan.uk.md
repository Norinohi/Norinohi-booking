# План рефакторингу

Мета: підготувати код до розширення (карта маршрутів, інфраструктура на карті, акаунти шкіперів,
AI-помічник, мобільний дизайн, третій провайдер) без зміни поведінки для користувача.

## Правила для кожного кроку

- Рефакторинг без зміни поведінки. Якщо крок вимагає змінити поведінку, це окремий коміт із поясненням.
- Кожен крок закінчується зеленими `pnpm check-types`, `pnpm test`, `pnpm test:db`, oxlint і oxfmt
  по змінених файлах.
- Публічні імпорти, якими користуються інші пакети, не ламаються: або лишаються реекспорти, або
  всі місця використання оновлюються в тому самому кроці.
- Один крок - один або кілька невеликих комітів у стилі Conventional Commits (`refactor(scope): ...`).
- Дві доріжки йдуть паралельно й не редагують ті самі файли: A - бекенд (`packages/*`, `apps/server`),
  B - фронтенд (`apps/web`, `packages/ui`). Спільні кроки (ролі) робляться послідовно: спершу A, потім B.
